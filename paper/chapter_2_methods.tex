\chapter{Methods}

\section{Data representation}

The code used in this project was written in python, using the Numba just-in-time compiler to achieve optimal execution speed (along best practices and algorithm optimizations in writing the code). From a development standpoint, every single Ising model configuration is represented in python as a $d$ dimensional numpy array of shape $N$ repeated $d$ times.

\begin{minted}[linenos, frame=lines]{python}

def new_random_ising(N: tuple[int, ...]):
    return np.ones(N, dtype = np.int8)

m = new_random_ising(tuple([N] * dim))

\end{minted}

Note that the data type that the numpy array contains is np.int8. In order to minimize storage space, the idea of using boolean variables to represent $1$ and $-1$ was considered, but was ultimately ditched in favour of storing integers. The latter grants faster executions when calculating physical observables (e.g.: energy, magnetization) at the loss of some disk space.

\br

Every array representing a single Ising model configuration is generated and stored in another numpy array of arbitrary length that represents the Markov Chain. This is done for a number of temperatures around the expected critical temperature, and is repeated for every lattice size under scrutiny and for every dimension. Ultimately, this data is stored in a hdf5 file for efficient i/o operations and in order to contextually add metadata and processed data (e.g.: autocorrelation time, thermalisation time, etc.) to the raw chain.

For every combination of dimension and lattice size, the generated raw data is stored in a numpy array of shape ($N_{temps}$, $N_{steps}$, [$N_{dim}$] \times \: $d$).
It's worth mentioning that for every lattice in every dimension periodic boundary conditions are used, which means that the first and last spins of the lattice are considered to be neighbours. This is obviously done to avoid edge effects as much as to simplify the handling of the data, as it allows using the same code for every spin in the lattice without having to consider special cases for the spins on the edges.

\br

A problem that arose during the development of the code was that the amount of data generated was too big to allocate in memory at once during runtime (the python scripts were run on a personal computer with 16GB of RAM). The solution to this problem was to chunk the data into smaller parts at runtime, and modify the code to load in memory these chunks, process them to obtain a partial result, discard the processed chunk, and then load the next to update the partial result until the entire dataset was processed. 

This allowed to process datasets of arbitrary size without running out of memory with negligible computation time overhead.

Partially because of this choice, but more in general to allow for efficient i/o operations, the compression algorithm chosen for the hdf5 files was lzf, which is a lossless compression algorithm that is very fast and has a good compression ratio.

\section{Monte Carlo Markov Chains}

\subsection{Generation}
\label{subsection:generation}

To study a system at a given temperature it is necessary to be able to generate a random configuration of said system. These random configurations are distributed as a function of their energy: as discussed the probability of a system of being in a state with energy $E$ in the canonical ensemble is given by:

\begin{equation}
	P(E) = \frac{\Omega(E) e^{-\beta E}}{Z}
\end{equation}

Now, it would be ideal to write this probability analytically to be able to compute it directly and use simple sampling techniques: to do that we would need to know how to write both $\Omega(E)$ and $Z$, but such an operation is, unfortunately, simply not possible. The sole computing of $Z$ would require summing over all possible configurations of the system, which in turn would require computing the energy of every single configuration. The number of possible configurations of a lattice with $N^d$ spins is $2^{N^d}$ and computing the energy of a single configuration is an $O(N^d)$ operation, which means that the overall complexity of computing $Z$ is $\bigO(N^d 2^{N^d})$, which is clearly not viable for any reasonable value of $N$.

\br

The solution to this problem is a Markov Chain Monte Carlo method, that is a method for generating a sequence of independent samples from a desired distribution without knowing the normalization constant. One algorithm that produces such a chain is the Metropolis-Hastings algorithm. This algorithm can draw samples from any probability distribution with probability density $P(x)$, provided that we know another function proportional to the density $P$ that we're able to compute analytically (in this case $e^{-\beta E}$) so that we can write $P(E) \propto e^{-\beta E}$.

The algorithm's idea is to start from a random configuration of the system and then to move to another configuration of the system with a set probability which is determined by the energy distribution.

The formal steps of the Metropolis algorithm in this use case are:

\begin{enumerate}
	\item Start from a random configuration of the system $x$.
	\item Randomly select a spin (or a number of spins) and flip it. We call this new configuration $x'$.
	\item Compute the energy difference of the two systems $\Delta E$.
	\item Set an acceptance probability parameter $\alpha$ based on the energy change and the temperature: $\alpha = \frac{T(x' \to x) P(x')}{T(x \to x') P(x)}$ where $P$ is the Boltzmann distribution. This is the core of the algorithm and it's what allows the Markov Chain to converge to the desired distribution.
	\item Accept the new configuration with probability $p = \min{\left(1, \alpha \right)}$, otherwise reject it and keep the current configuration. That is, if the new configuration is more probable than the current one, accept it, otherwise accept it with probability $\alpha$ (that is, a probability proportional to the ratio of the two probabilities).
	\item Add the current configuration to the Markov Chain.
	\item Repeat steps 2-6 for a number of iterations. The elements of the chain after enough iterations are distributed as  $e^{-\beta E}$
\end{enumerate}

The "trick" that makes this algorithm work is that computing $\alpha$ the ratio of the Boltzmann factors is sufficient, as the normalization constants $Z$ cancel out.

Note that randomly selecting a spin and flipping it (step 2) is effectively moving to another random configuration of the system close to the current one. This movement is interpreted as a random sample from a distribution centered around the current configuration. Picking a random spin to flip is an arbitrary choice, and other methods could be used to select a neighboring configuration, but has the advantage that the probability of moving from $x$ to $x'$ ($T(x \to x')$) is the same as moving from $x'$ to $x$ ($T(x' \to x)$), which is the Hastings condition of the algorithm. This condition is not striclty necessary, but it simplifies the computation of $\alpha = \frac{e^-\beta E'}{e^{-\beta E}} = e^{-\beta \Delta E}$ to be only dependent on the energy delta and temperature.

\begin{minted}[linenos, frame=lines, breaklines]{python}

def _metropolis_ising_1d(model: np.ndarray, T: float, steps: int):
    '''
    1D version of Metropolis-Hastings for Ising model.
    '''

    curr_model = np.copy(model)
    models_samples = np.empty((steps,) + curr_model.shape, dtype = curr_model.dtype)
    N = curr_model.shape[0]
    
    for i in range(steps):
        idx0 = np.random.randint(0, N)
        spin = curr_model[idx0]
        forward = (idx0 + 1) % N
        backward = (idx0 - 1) % N
        deltaE = 2.0 * spin * (curr_model[forward] + curr_model[backward])
        
        accept_probability = np.minimum(1.0, maxwell_boltzmann_statistics(deltaE, beta=1.0 / T))
        if np.random.random() <= accept_probability:
            curr_model[idx0] = -curr_model[idx0]
        
        models_samples[i] = curr_model
    
    return models_samples

\end{minted}

Also note that since $\alpha$ depends only on the relative energy change the computation can be greatly optimized by computing only the energy change given by the single spin flip, instead of computing the energy of two entire configurations.

As mentioned, this algorithm can work by selecting a number of spins to flip at each proposal. In this project, only the single spin flip method was explored, but the code is written in a way that allows for easy extension to multiple spin flips.

Another arbitrary choice is the starting configuration of the system: two choices make sense and were explored in this project, that is, starting from a random configuration (hot start) or starting from a configuration with all spins aligned (cold start). The former has the advantage of being unbiased, while the latter has the advantage of being closer to the expected configuration at low temperatures, which means that the chain will thermalize faster. Thermalization is discussed properly in the next section, but in short is the process by which the Markov Chain "forgets" its initial configuration and converges to a stationary distribution. Since in practice the Markov Chains were constructed starting from low temperatures and then using the last configuration of the chain as the starting configuration for the next temperature, the cold start was used in this project as it granted a practically thermalized state from the very beginning. Of course, this does not mean that no configuration is ever discarded, but this grants the certainty that the chain does not have thermalization issues for the first few temperatures.

\subsection{Analysis}

As stated, a Markov Chain suffers from a recency bias, and the set of configurations of the chain is not very useful as a real sample set since the elements are not independent: on the contrary, they are very closely correlated and the presence of correlations between samples would lead to biased results during analysis.

The extraction of decorrelated data is a problem composed of two parts: the thermalisation and the autocorrelation time. The first one is the number of steps that the Markov Chain needs to reach a stationary distribution, while the second one is the number of steps that need to exist between successive samples before they can be considered independent.

\begin{figure}[htbp]
	\centering
	\includegraphics[width=1.\textwidth]{../pics_and_anims/autocorrelation_plot.pdf}
	\caption{Example of autocorrelation function (of the energy) for a Markov Chain.}
	\label{figure:autocorrelation_plot}
\end{figure}

The plot in figure \ref{figure:autocorrelation_plot} shows the autocorrelation function of one Markov Chain. The autocorrelation function can be defined as:

\begin{equation}
	\rho(\tau) = \frac{\mathbb{E}[(X_{t + \tau} - \mu)\overline{(X_t - \mu)}]}{\sigma^2}
\end{equation}

where $\mathbb{E}$ denotes the expected value and $X$ are the observable values measured on the configurations. 

The following is the code used to estimate $\rho$ from the Markov Chain:

\begin{minted}[linenos, frame=lines, breaklines]{python}

def autocorrelation(t, observables: np.ndarray):
	'''
	Computes the autocorrelation function's value given:
	- A time (step) t
	- An array of observable values along the Markov chain
	'''

	N = len(observables)
	if t >= N or t < 0:
		return 0.0

	var = np.var(observables)

	if var == 0:
		return 0.0

	centered = observables - np.mean(observables)
	autocov = np.sum(centered[:N - t] * centered[t:]) / N

	return autocov / var

\end{minted}

and it's computed with the alternative formula shown in the code snippet for performance's sake.

The function $\rho$ quantifies the similarity between observations of a random variable (energy, in this case) at different points in time, which can be used to develop methods to extract uncorrelated samples. Specifically, we see that $\rho$ needs a transient time to reach a state of close-to-zero values and after this time it remains close to zero.

Two parameters can be defined from the autocorrelation function:

\begin{itemize}
	\item The exponential autocorrelation time $\tau_{\text{exp}}$, which is the time it takes for the autocorrelation function to decay into the equilibrium region.
	\item The integrated autocorrelation time $\tau_{\text{int}}$, which is the sum of the autocorrelation function over all time lags, which is a measure of the overall correlation in the data. It's defined as $$\tau_{\text{int}} = \frac{1}{2} + \sum_{t=1}^{\infty} \rho(t)$$.
\end{itemize}

To sample uncorrelated data from the Markov Chain two numbers are needed: 

\begin{itemize}
	\item The number of steps to discard in front of the chain. This represents the thermalisation time, that is, the number of steps that the chain needs to reach a configuration that is representative of the stationary distribution at a certain temperature, in other words, the number of steps that the chain needs to "forget" its initial configuration. Conceptually, this is related to $\tau_{\text{exp}}$.
	\item The number of steps to skip between samples (to avoid correlation between samples). This number is related to $\tau_{\text{int}}$, and is usually set to a multiple of it (e.g.: $2 \tau_{\text{int}}$).
\end{itemize}

A number of methods exist to estimate these two numbers, in this project only two are explored.

Note that theoretically speaking $\tau_{\text{exp}}$ can be neglected if the chain is long enough, that is, if we sample from a high enough multiple of $\tau_{\text{int}}$ (e.g. $1000 \tau_{\text{int}}$), because the exponential decay will have already occurred. However, in practice it is always better to discard a number of steps in front of the chain to avoid the initial transient behavior. Discarding too many steps can be a problem too though, because it can lead to a loss of information and a decrease in the effective sample size (and relative errors). Practically, the number of steps to discard in this experiments will be set to $20 \tau_{\text{int}}$, which is a somewhat stable estimate of $\tau_{\text{exp}}$. Dedicated techniques to study $\tau_{\text{exp}}$ itself will not be explored.

\br

\subsubsection{Sokal's method}

A. Sokal describes a method to estimate the integrated autocorrelation time $\tau_{\text{int}}$ in his lecture notes "Monte Carlo Methods in Statistical Mechanics: Foundations and New Algorithms" (1996). The following section discusses the method and its implementation in this project.

The natural estimator of $\tau_{\text{int}}$ would seem to be

\begin{equation}
    \widehat{\tau}_{\text{int}} \equiv \frac{1}{2} + \sum_{t=1}^{n} \widehat{\rho}(t)
\end{equation}

but this is not really the case, because this estimator has a variance that does not go to zero as the sample size $n$ goes to infinity, so it cannot be a good estimator of $\tau_{\text{int}}$. Qualitatively speaking, this happens because the sample autocorrelations $\widehat{\rho}(t)$ for big $t$ contain much noise but little signal, and there are so many of them (order $n$) that the noise adds up to a total variance of order 1. The solution is to cut off the sum using a window $\lambda(t)$ which is $\approx 1$ for small $t$ but $\approx 0$ for large $t$:

\begin{equation}
    \widehat{\tau}_{\text{int}} \equiv \frac{1}{2} + \sum_{t=1}^{n} \lambda(t) \widehat{\rho}(t).
\end{equation}

This retains most of the signal but discards most of the noise. A good choice is the rectangular window

\begin{equation}
    \lambda(t) = \begin{cases} 
    1 & \text{if } t \le M \\ 
    0 & \text{if } t > M
    \end{cases}
\end{equation}

where M is an arbitrarily chosen cutoff. The choice of M is a tradeoff between bias and variance: if M is too small, we throw away too much signal and the estimator is biased; if M is too large, we throw away too little noise and the estimator has a large variance. A good choice would be, for example, to take M to be the first t for which $\widehat{\rho}(t)$ is negative.

The method implemented in the code is a self-consistent windowing method, where the window size is determined dynamically at runtime. The idea is to choose a window size $M$ that is proportional to the estimated integrated autocorrelation time $\tau_{\text{int}}$, specifically $M = c \tau_{\text{int}}$ for some constant $c$. This allows the window size to adapt to the data, providing a balance between bias and variance in the estimator.

\begin{minted}[linenos, frame=lines, breaklines]{python}

def tau_int_sokal(observables, c = 15.0):
    '''
    Computes the integrated autocorrelation time using a self-consistent windowing method.
    c: The windowing parameter. The bigger c, the longer the window.
        longer window: tau has less bias
        shorter window: tau has less variance
    NOTE: higher c values yield more accurate results but require more computation time.
    '''

    N = len(observables)
    var = np.var(observables)
    
    if var == 0.0:
        return 0.0

    centered = observables - np.mean(observables)
    tau = 0.5

    for t in range(1, N):
        autocov_t = np.sum(centered[:N-t] * centered[t:]) / N
        tau += autocov_t / var

        if t >= c * tau:
            return tau

    return tau

\end{minted}

The method is called self-consistent because the window size $M$ is determined based on the estimated value of $\tau_{\text{int}}$ itself. The algorithm iteratively computes the autocorrelation function and updates the estimate of $\tau_{\text{int}}$ until the window size $M$ is reached. This ensures that the estimator is both efficient and accurate, as it adapts to the characteristics of the data being analyzed.

\subsubsection{Data blocking method}

While Sokal's method is based on summing over the autocorrelation function in a particular way, the data blocking method presented in the work "Error estimates on averages of correlated data" by H. Flyvbjerg and H. G. Petersen operates in a fundamentally different way.

Let's consider a Markov Chain of length $N$ of configurations ${x_i}$ with variance $\sigma^2$ and an observable $O$ measured on each configuration. Now suppose we simplify this Chain by averaging the values of the observable $O$ of every consecutive $k$ elements. This will produce a new chain of length $N_b = N / k$ of block averages $\bar{O}_i$ that are less correlated than the original chain. One can then take advantage of the law:

\begin{equation}
	\label{eq:vk}
	V_k = \frac{\sigma^2}{k} (1 + 2 \tau_{\text{int}})
\end{equation}

to build an estimator of $\tau_{\text{int}}$:

\begin{equation}
	\tau_{\text{int}}(k) = k \frac{V_k}{2 \sigma^2}
\end{equation}

where the $-\frac{1}{2}$ term was dropped in accordance with Sokal's alternative definition of $\tau_{\text{int}}$ (even though its a negligible correction).

Note that \ref{eq:vk} is intended to be a correction to the variance of the mean $V_k$ for a chain of truly uncorrelated data:

\begin{equation}
	\label{eq:vks}
	V_k = \frac{1}{N_b - 1} \sum_{i = 1}^{N_b} (\bar{O}_i - \bar{O})^2 = \frac{\sigma^2}{k}
\end{equation}

and the correction factor can be written as a function of $\tau_{\text{int}}$ only in the limit $N \gg \tau_{\text{int}}$.
To verify that these laws are consistent with each other, one can see that for truly uncorrelated data $\tau_{\text{int}} \to 0$, and so equation \ref{eq:vk} reduces to equation \ref{eq:vks} for $N = k$ (or $N_b = 1$ or $N \gg \tau_{\text{int}}$). 

\br

Now, the idea is that since $\tau_{\text{int}} = \tau_{\text{int}}(k)$ it can be studied as a function of $k$. This can be done by iterating the simplification process described above on the chain in order to create a coarser chain at every iteration, where $\bar{O_i (k)}$ are less correlated at every iteration

The blocks will contain $k$ elements, and their size will double at every iteration. This means that for every iteration the number of blocks $N_b$ will be halved and $k$ will be doubled. The first iteration is $k = 1$ and $N_b = N$.

For every $k$ the procedure is as follows:

\begin{enumerate}
	\item Divide the chain into $N_b$ blocks of size $k$. The number of blocks is then $N_b = N / k$ and compute the average of the observable $O$ in each block. This is equivalent to averaging the observables of every two consecutive blocks of the previous iteration.
	\item Compute the variance of the new set of block averages.
	\item Compute $\tau_{\text{int}}(k)$ as $\tau_{\text{int}}(k) = \frac{1}{2}(k \frac{V_k}{\sigma^2} - 1)$.
\end{enumerate}

The estimate $\tau_{\text{int}}(k)$ will converge to the true value of $\tau_{\text{int}}$ as $k$ increases.

After a certain value of $k$ the limit $k \gg \tau_{\text{int}}$ will be reached (in a numerical sense) and the estimate for $\tau_{\text{int}}$ will converge to a plateau (because $V_k$ will be stable). The value of the plateau is then taken as the final estimate of $\tau_{\text{int}}$.

It's important to note that this method can be used on a chain that has reached the stationary distribution, from the beginning. So, in the actual implementation, the thermalisation time is computed as $20 \tau_{\text{int}}^{\text{Sokal}}$ estimated with Sokal's method, and then the data blocking method is applied to the chain after discarding the first $20 \tau_{\text{int}}^{\text{Sokal}}$ steps. 

The implementation is shown in the following code:

\begin{minted}[linenos, frame=lines, breaklines]{python}

def tau_int_blocking(observables, burn_in = None, c_blocking = 15.0):
    '''
    Computes the integrated autocorrelation time using the data blocking method.
    observables: ndarray of observable values along the Markov chain.
    burn_in: int, optional
        The number of initial samples to discard as burn-in.
        if None, burn_in is estimated as 20 tau_int computed with the Sokal method.
    '''

    N = len(observables)

    if burn_in is None:
        tau0 = tau_int_sokal(observables, c = c_blocking)

    observables = observables[burn_in:]
    N = len(observables)

    var = np.var(observables)

    current_blocks = observables.copy()
    tau_estimates = []
    block_size = 1 # k
    Nb_array = [] # Number of blocks for each block size
    Nb = N # Number of blocks for the current block size (Nb_array[0])

    while Nb >= 2:
        # Estimation
        mean_blocks = np.mean(current_blocks)
        var_blocks = np.sum(np.power(current_blocks - mean_blocks, 2)) / (Nb - 1)
        tau_estimate = .5 * (block_size * (var_blocks / var) - 1)
        tau_estimates.append(tau_estimate)
        Nb_array.append(Nb)

        # Blocking
        if Nb % 2 != 0:
            current_blocks = current_blocks[:-1]  # Discard the last block if odd number of blocks
            Nb -= 1
        Nb //= 2
        current_blocks = 0.5 * (current_blocks[::2] + current_blocks[1::2])
        block_size *= 2
	
    for i in range(len(tau_estimates) - 1):
        if Nb_array[i] < 30:
            return float(tau_estimates[i])

        diff = abs(tau_estimates[i + 1] - tau_estimates[i])
        err = (tau_estimates[i] + 0.5) * np.sqrt(2.0 / (Nb_array[i] - 1)) 
        
        if diff < err:
            return float(tau_estimates[i])

    return float(tau_estimates[-1])

\end{minted}

\subsection{Improvement to the MCMC algorithm: sweeps}

It is true that the two methods are shown to be quite compatible with each other, with produced estimations of $\tau_{\text{int}}$ that are generally in good agreement. The errors, on the other hand, are quite big, specifically close but not at $T_C$. This is specifically true for the data blocking method. Since the errors given by this method scale as $\sqrt{2 / (N_b - 1)}$ where $N_b$ is the number of blocks, the only way to reduce them is to increase the length of the chain.

This option was not viable. To try to fix the problem, another approach was explored, that is, to change the way of building the chain. Let's define a "sweep" as the process of applying steps 2-5 of the Metropolis-Hastings algorithm (explained in Section \ref{subsection:generation}) to a configuration $N^d$ times. This is an arbitrary choice, with the rationale that a sweep is the amount of steps needed to give every spin in the lattice a chance to flip. The idea is to build the chain by adding a configuration to it only after every sweep: this ensures a lower correlation between successive configurations in the chain, and so a lower $\tau_{\text{int}}$. This is a pretty standard approach in the literature, and is used in many implementations of the Metropolis-Hastings algorithm.

This new approach allows for much shorter chains to be used in theory, which means that more accurate results can be obtained with less computational effort. All of the production and analysis of the chains was redone with this new approach with chains with length of one less order of magnitude than before.

The results are shown in figures \ref{figure:tau_int_1D_comparison_sweeps}, \ref{figure:tau_int_2D_comparison_sweeps} and \ref{figure:tau_int_3D_comparison_sweeps}. The correlation between the two methods is still clear, and the errors are significantly smaller than before. The only point where both methods fail is at the critical temperature, where, again, this is the expected behavior as the correlation length diverges and so does $\tau_{\text{int}}$.
